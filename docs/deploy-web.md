# Deploying the web dashboard to Cloudflare Pages

`apps/web` is a fully static SvelteKit site (`@sveltejs/adapter-static`). Every page is
prerendered into `apps/web/build`; Cloudflare Pages only serves files, there is no server code.

## What the build contains

| File               | Purpose                                                                    |
| ------------------ | -------------------------------------------------------------------------- |
| `index.html`       | landing page                                                               |
| `app.html`         | the dashboard shell (`/app`); it renders in the browser                    |
| `privacy.html`     | privacy policy (`/privacy`), the URL Google asks for on the consent screen |
| `404.html`         | shown for unknown paths                                                    |
| `_headers`         | security headers and long caching for hashed assets (`static/_headers`)    |
| `_app/immutable/*` | hashed JS and CSS                                                          |

Pages serves `/app` from `app.html` and `/privacy` from `privacy.html` automatically.

The Content-Security-Policy is a `<meta>` tag generated by SvelteKit (`vite.config.ts`). It
allows only this site, Google Identity Services (`accounts.google.com/gsi/`) and the Google APIs
used for sync. If you add a remote resource, the CSP must allow it, and CLAUDE.md's privacy rule
says you probably shouldn't.

## Option A: connect the GitHub repository (recommended)

1. In the Cloudflare dashboard: **Workers & Pages → Create → Pages → Connect to Git**, and pick
   the repository.
2. Build settings:

   | Setting                | Value                                                                  |
   | ---------------------- | ---------------------------------------------------------------------- |
   | Framework preset       | None                                                                   |
   | Build command          | `pnpm install --frozen-lockfile && pnpm --filter @applicliq/web build` |
   | Build output directory | `apps/web/build`                                                       |
   | Root directory         | `/` (the repository root, so the workspace packages are available)     |

3. **Environment variables** (Production, and Preview if you want sign-in on preview URLs):
   - `VITE_GOOGLE_CLIENT_ID`: the Web application OAuth client ID
     ([google-setup.md](google-setup.md)). Without it the site builds, and `/app` says sync isn't
     set up.
   - Node comes from `.node-version` (22) and pnpm from `packageManager` in `package.json`.
4. **Save and Deploy.** Every push to `main` deploys production; other branches get preview URLs.

## Option B: deploy from your machine

```bash
VITE_GOOGLE_CLIENT_ID=1234-def.apps.googleusercontent.com pnpm deploy:web
```

This builds the site and uploads `apps/web/build` with Wrangler (`pnpm dlx`, nothing installed in
the repo). The first run asks you to log in to Cloudflare and creates the `applicliq` project
(`apps/web/wrangler.toml`). With `apps/web/.env` filled in, the variable is picked up from there.

## After the first deploy

1. In Google Cloud, add the site's origin (e.g. `https://applicliq.pages.dev`, plus any
   custom domain) to the Web client's **Authorized JavaScript origins**. Without it, sign-in on
   `/app` fails with `redirect_uri_mismatch` / "origin not allowed".
2. On the OAuth consent screen (**Google Auth Platform → Branding**), set:
   - **Application home page**: `https://<your-domain>/`
   - **Application privacy policy link**: `https://<your-domain>/privacy`
   - **Authorized domains**: your domain (`pages.dev` subdomains can't be verified, so use a
     custom domain before submitting the app for verification).
3. Open `/app`, sign in, and check that the sync menu says **Synced just now**.

## Preview locally

```bash
pnpm --filter @applicliq/web build && pnpm --filter @applicliq/web preview
```

The preview runs at http://localhost:4173; add that origin to the Web client to test sign-in
there. `_headers` only applies on Cloudflare, not in the local preview.
